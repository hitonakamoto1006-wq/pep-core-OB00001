PEP39CL-0003 Binary Layout

Version: 0.1 Draft

===========================================================

1.  Abstract

This document defines the binary payload used by PEP39CL.

The binary payload specifies how entropy, version, checksum and reserved
bits are organized before encoding into the mnemonic.

This specification does not define the encoding algorithm.

===========================================================

2.  Goals

The binary layout SHALL:

-   Be deterministic.
-   Be compact.
-   Be forward compatible.
-   Support versioning.
-   Support checksum validation.

===========================================================

3.  Binary Payload

  ---------- ---------- ----------- -----------
  Version    Entropy    Checksum    Reserved

  ---------- ---------- ----------- -----------

===========================================================

4.  Binary Fields

Version

Purpose: Identify the PEP39CL specification version.

Size: 8 bits

Current Value: 0x01

------------------------------------------------------------------------

Entropy

Purpose: Random value generated by a Cryptographically Secure Random
Number Generator (CSPRNG).

Size: 256 bits

------------------------------------------------------------------------

Checksum

Purpose: Detect typing errors and corrupted mnemonics.

Algorithm: SHA-256

Size: 8 bits

------------------------------------------------------------------------

Reserved

Purpose: Reserved for future extensions.

Current Value: All reserved bits SHALL be zero.

Size: 28 bits

===========================================================

5.  Payload Size

Version : 8 bits Entropy : 256 bits Checksum : 8 bits Reserved : 28 bits

Total : 300 bits

===========================================================

6.  Field Ordering

Version ↓

Entropy ↓

Checksum ↓

Reserved

The field order SHALL NOT change in Version 1.

===========================================================

7.  Reserved Bits

Reserved bits SHALL be zero when generating a mnemonic.

Implementations SHALL ignore reserved bits only if explicitly permitted
by a future specification.

Version 1 defines no reserved features.

===========================================================

8.  Validation

9.  Read Version

10. Verify supported Version

11. Read Entropy

12. Verify Checksum

13. Verify Reserved Bits

14. Accept Payload

===========================================================

9.  Compatibility

Future versions MAY redefine the reserved bits.

Future versions SHALL NOT change the position of the Version, Entropy or
Checksum fields.
